# План: сбой сервера 21.11 — серии не прерываются, отчёты помечены

Дата: 2026-11-22. Владелец утвердил план в чате («ок»), решение по счётчику:
**день сбоя перешагивается, но в серию не прибавляется** (серия = число реальных ответов).

## Инцидент (факты с прода, read-only)
- 21.11 утром у сервера 78.17.84.182 отвалилась сеть/DNS (напоминание 03:00 UTC не ушло: 0/43),
  затем машина легла; перезагрузка 17:34 UTC (22:34 ЕКБ), сервис поднялся чисто.
- Опросы 21.11: только 3 (после перезагрузки) — #79 Иванин 18:00, #94 Гизатуллина 18:22, #76 Анферов 21:52 UTC.
- 22.11 ответил #103 Калетин — серия сломалась в 1 (была длинной, всего 48 опросов).
- Корень: `database.py save_survey` идёт назад по датам опросов, любой пропуск обрывает цепочку;
  понятия «день сбоя» нет.

## Решения
1. Реестр `bot_settings.outage_dates` (JSON-список ISO-дат). `Database.get_outage_dates()` /
   `set_outage_dates()`. Битое значение → пустое множество + лог (fail-safe).
2. Чистая функция `database.compute_streak(survey_dates, anchor, outage_dates)`:
   день с опросом → +1; день сбоя без опроса → перешагнуть; иначе → стоп.
   Реальный опрос в день сбоя считается обычным днём. `save_survey` использует её (якорь = сегодня).
3. `Database.recalc_streaks(dry_run=True)` — пересчёт всех атлетов с якорем = макс. дата опроса
   (семантика «серия на момент последнего ответа», как в реконструкции 11.11).
   Меняет только survey_streak; total_surveys/last_active не трогает; идемпотентен.
4. Скрипт `scripts/repair_streaks_outage.py` (правило 6): dry-run по умолчанию, `--live`,
   `--outage DATE` (добавляет в реестр). Перед --live — вне-серверная копия БД (правило 7).
5. Пометка во всех отчётах, накрывающих день сбоя. Текст:
   `⚠️ Сбой сервера: 21.11 — опросы не собирались, серии не прерваны` (модуль `outage.py`:
   `outage_note_for_period(dates, start, end)`, `recent_outage_note(dates, today, window=3)`).
   - недельный PNG (`weekly_report.generate_weekly_report(outage_note=...)`, строка над футером,
     без эмодзи — PIL их не рисует) + подпись Telegram в `bot._send_weekly_reports`;
   - Excel (`handlers_reports.generate_xlsx_report`): строка на «Сводке», приписка в подзаголовках
     «По дням» и листов команд, «⚠» в шапке колонки дня сбоя в матрице, приписка в caption;
   - текстовые отчёты `reports.py` (атлет/команда): примечание в шапке + отметка дня без опроса;
   - недельная сводка тренерам (`handlers_admin._coach_summary_text`): примечание + знаменатель
     `атлеты × (7 − дни_сбоя_в_окне)` (моё решение, чтобы % участия не врал);
   - дашборд «На сегодня» (`dashboard.build_today_dashboard`) и дневная сводка админам
     (`bot._send_daily_reminder`): баннер, если сбой в окне 3 дней (сегодня/вчера/позавчера).
6. Окно отчётов = окну SQL-выборки (`today − days … today`).

## Не делаем
- Фиктивных опросов за 21.11 (данные несовершеннолетних не выдумываем).
- Правок trend-алертов (пропуск дня может чуть повлиять на тренды — осознанно).
- «Лечения» пропусков, не связанных со сбоем.
- Админ-UI управления реестром сбоев (пополняется скриптом/setting).
